# audit

Скилл для ревью того, что **уже написано и лежит на диске** — инструмента,
скрипта, дерева конфигурации, набора документов. Результат один файл:
`review-YYYY-MM-DD-<object>.md` в корне проекта.

Скилл ничего не чинит. Рецензировать и править — разные работы: проход, взявшийся
за первую находку, перестаёт искать остальные и до третьей уже не доходит.

```
ты:     /audit bin/mytool
скилл:  Using audit on bin/mytool — findings go to review-2026-09-18-mytool.md
        … baseline, пробы, воспроизведения …
        A: 7, B: 3, C: 4, D: 4 open questions. Nothing was fixed.
```

## Когда `audit`, а когда рецензент pull request'а

| Что на входе | Чем смотреть |
|---|---|
| pull request, ветка под слияние, изменение в истории git | инструменты ревью pull request'ов — они построены на `gh pr diff` |
| инструмент, скрипт, дерево конфигурации, набор документов на диске | этот |

Рецензенты pull request'ов на каждый прогон поднимают несколько агентов
параллельно. На изменении с историей и владельцами это себя окупает; когда
pull request'а нет — а для личного инструмента это обычное дело, — у них просто
нет входа. **Здесь одна сессия и ни одного субагента.** Если проходу нужны
параллельные агенты, объект слишком велик: бери часть и скажи какую.

## Что даёт проход

Один файл в Markdown, разделы названы по последствиям, а не по темам:

| Раздел | Вопрос |
|---|---|
| **A. Дефекты** | что делает не то — каждый с командой воспроизведения, классом (silent wrong result / visible failure / damage), радиусом правки и тестом, который его закрывает |
| **B. Документация** | где текст расходится с кодом |
| **C. Стоимость** | что обходится слишком дорого — только с числом, которое напечатала команда |
| **D. Суждение** | что сделано верно и трогать не надо, что спорно; предложения, а не задания |
| **Что дефектом НЕ является** | проверено и оказалось правильным, чтобы следующий не тратил время |
| **Готово, когда** | приёмочные команды, каждая с кодом возврата, который должна дать |

И две вещи, ради которых файл исполним, а не познавателен: **инварианты**,
которые правка ломать не имеет права, взятые из слов самого проекта, и **порядок
правок** — какие пункты делят один код и что остаётся открытым, пока едут
остальные.

## Правила, которым проход подчиняется сам

- **Сначала воспроизвести, потом утверждать.** Нет команды — нет находки.
- **Запускать на сломанном входе.** Проверка, ни разу не запущенная против
  поломки, которую описывает, не проверена.
- **Цитата из документации — это гипотеза.** Если тяжесть находки держится на
  поведении хоста или среды выполнения, это поведение показывают на этой машине,
  либо
  пункт помечают непроверенным.
- **Вердикт читать по коду возврата.** Сессия работает внутри хуков и обёрток,
  переписывающих вывод; когда объект той же природы, экран не доказывает ничего.
- **Песочница из `mktemp -d`, ничего не удалять.** Каждая итерация чиста,
  потому что новая, — и ни одному пробному скрипту не нужен `rm`.
- **Не выходить за пределы проекта.** Соседний проект на этой машине не
  свидетельствует об этом.
- **Один объект за проход**, а после примерно 600 строк кода объект делится по
  шву, который и так есть: реализация и её порт, библиотека и команда-драйвер.

## Установка

```bash
git clone <этот репозиторий> audit && cd audit
./install.sh                 # во все найденные: Claude Code, Opencode, Codex
./install.sh --dry-run       # показать, что произойдёт, ничего не писать
./install.sh --skills-dir D  # поставить в D вместо автоопределения
```

Windows: `.\install.ps1`, флаги те же.

Скилл — это три файла Markdown. Ни бинаря, ни записи в `PATH`, за пределы
`$HOME` ничего не пишется. Повторный запуск меняет только изменившееся; файл,
который перезаписывают, копируется в `.bak`, только если такого содержимого нет
в этом репозитории, — правка руками единственное, чего git не вернёт.

Удаление: удалить каталог `<skills-dir>/audit`.

## Что где лежит

```
skills/audit/SKILL.md              сам проход — что делать и в каком порядке
skills/audit/references/
    template.md                    скелет файла ревью, по слотам
    domains.md                     формы, которые пропускают чаще всего, по доменам
install.sh / install.ps1           копирование в каталоги скиллов ассистентов
release.sh                         версия ↔ журнал ↔ тег ↔ HEAD ↔ копии
CHANGELOG.md                       что изменилось в каждом выпуске
```

Обе страницы `references/` грузятся **по надобности**: `template.md` — когда
файл уже пишут, `domains.md` — только если объект одного из описанных там родов.
Обычный проход не платит ни за одну.

## Выпуск

```bash
./release.sh check     # версия ↔ журнал ↔ тег ↔ HEAD ↔ установленные копии
./release.sh tag       # создать тег, в него уезжает секция журнала
```

`check` сверяет каждую установленную копию с источником **пофайлово**, причём
список файлов спрашивает у источника, а не берёт из написанного руками перечня.
